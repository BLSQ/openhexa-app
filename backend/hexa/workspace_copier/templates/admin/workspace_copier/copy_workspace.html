Copy a workspace between servers. A token is required on both sides, this server included. The copy runs in the background: submitting queues it and opens its run page, where logs appear as it progresses. Source/target credentials are stored encrypted until the run ends, then erased.

When source and target are both "This server", the workspace database and static web apps are copied too: they need direct access to this server's database and git server.

To make several copies in a row, this browser remembers the form: servers, target organization and resource choices are kept until you forget them, tokens only until this tab is closed.

{% trans 'Creating the service account tokens' %}

  1. On each server, open Django admin › User management › Service accounts (here on this server) and add a service account. An email address is all it needs.
  2. Copy the token from the yellow message shown right after saving: it is displayed only once. If it is lost, select the account in the list and run the "Rotate tokens" action to get a new one.
  3. Give the account access like any other user. On the source, make it a member of the workspace to copy. On the target, it must be allowed to create workspaces in the target organization, or be an editor (or above) of the existing workspace to copy into.
